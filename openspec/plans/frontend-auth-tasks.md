**Out of scope for this file (later plans)**

**Product defaults (resolved)**

| Concern | Choice |
|---|---|
| AuthProvider (backend) | Supabase (already); Flutter uses Supabase Auth SDK for sign-up/sign-in/session |
| API contract | Prefer OpenAPI-generated typed client from FastAPI `/openapi.json`; interim typed Dio façade only if codegen tooling is blocked — must match `/api/v1` auth/users/documents paths |
| State | Riverpod 3 |
| Models | Freezed (+ json_serializable for DTOs) |
| Routing | GoRouter + reusable auth guard |

**Conventions**
- Loop per chunk: failing test → implement → (widget test where UI) → review vs OpenSpec auth + architecture §2.1–§2.3 + design-system composition rule → fix → commit.
- Prefer small sequential commits; never one giant “frontend-auth” commit.
- Feature public surface = barrel `features/auth/auth.dart` only. No `features/auth/data` imports outside auth.
- Feature screens: layout + `Lexivo*` atoms only. No ad-hoc `ElevatedButton` / raw `TextField` / custom error chrome.
- All backend HTTP via `core/network` client — no `Dio.get` inside feature code.
- Prefixes: package `lexivo`; UI `Lexivo*`; never `Nexora*`.

**Design-system gap flag (must resolve before password UI)**
- `LexivoTextField` today lacks `obscureText` / password visibility. Auth sign-up/sign-in **MUST NOT** drop to a raw `TextField`.
- Flagged need: add `obscureText` (+ optional visibility-toggle trailing control) to `LexivoTextField` under `core/design_system` with unit/golden coverage, then consume from auth. Tracked in §0.G — not an auth one-off.
